v0.1 · 초기 버전

nondev-kit 사용 안내

개발자가 아닌 사람이 AI로 웹사이트나 앱을 만들 때 쓰는 Claude Code 플러그인입니다. 무엇을 만들지는 내가 정하고, 어떻게 만들지는 Claude가 정합니다.

1. 시작하는 법

설치해서 쓰는 방법과, 내려받은 폴더를 직접 불러오는 방법이 있습니다. 아래는 폴더를 직접 불러오는 방법입니다.

1

터미널에서 Claude Code에 로그인하기

터미널을 열고 claude를 실행한 뒤 /login을 입력합니다. 한 번만 하면 됩니다.

2

새 프로젝트용 빈 폴더 만들기

만들 앱이 들어갈 폴더입니다. 이름은 자유롭게 정하면 됩니다.

mkdir ~/Desktop/my-app
cd ~/Desktop/my-app
3

플러그인을 켠 채로 Claude Code 실행하기

claude --plugin-dir "내려받은 nondev-kit 폴더 경로"

이 방식은 실행할 때마다 위 명령으로 시작해야 플러그인이 켜집니다.

4

만들고 싶은 것을 말하기

"앱 만들어줘"처럼 막연하게 말해도 됩니다. 그러면 Claude가 바로 만들지 않고 먼저 질문합니다.

설치해서 쓰기 (권장)

Claude Code 안에서 아래 두 줄을 한 번만 입력하면 그 뒤로는 자동으로 켜집니다. 

/plugin marketplace add applelog/nondev-kit
/plugin install nondev-kit@nondev-kit

2. 쓰면 이렇게 흘러갑니다

파란 글씨는 내가 하는 일, 초록 글씨는 Claude가 하는 일입니다.

나말하기"앱 만들어줘"
→
Claude질문하기고르는 질문 몇 개
→
나계획 확인짧은 요약에 "좋아"
→
Claude만들기쉬운 말로 설명하며
→
Claude점검·기록보안 점검, 개발일지

예시 대화

가계부 앱 만들어줘
좋아요. 만들기 전에 몇 가지만 여쭤볼게요. 누가 쓰나요? ① 나 혼자 ② 가족이나 친구 몇 명 ③ 누구나
① 나 혼자
가장 중요한 기능 하나만 고른다면요? ① 지출 빠르게 적기 ② 월별 통계 보기 ③ 예산 넘으면 알림
①
정리하면 이렇습니다: 혼자 쓰는 웹 가계부, 핵심은 지출 빠르게 적기, 로그인 없음, 비용 0원. 이대로 시작할까요?

실제 질문 문구는 상황에 따라 달라집니다. 위는 흐름을 보여주는 예시입니다.

질문이 끝나면 받는 계획서

이 요약을 보고 "좋아"라고 하면 만들기 시작합니다. 기술은 Claude가 고르고, 이유를 한 줄씩 적어 줍니다.

무엇을 / 누구를 위해한 문장으로 정리한 제품과 사용자
첫 버전첫날 반드시 되어야 하는 한 가지
화면화면마다 사용자가 무엇을 하는지 한 줄씩
완료 조건내가 직접 해 보고 확인할 수 있는 것 2~4개. 예: "지출을 적고 새로고침해도 남아 있다". 나중에 오류가 나면 이것이 "정상"의 기준이 됩니다.
나중에 / 안 하는 것첫 버전에서 미루는 기능과 일부러 빼는 것
Claude가 정한 것 / 추측한 것도구와 이유, 예상 월 비용, 묻지 않고 가정한 것

3. 들어 있는 것 7가지

대부분 자동으로 작동합니다. 따로 외울 명령은 없습니다.

작업 규칙

쉬운 말로 설명하기, Claude가 혼자 정해도 되는 범위, 기본 보안 습관.

매 세션 자동

안전 검사

위험한 명령 4종류를 실행 전에 막거나 확인을 요구합니다.

모든 명령 전 자동

시작 질문

막연한 요청을 고르는 질문 몇 개로 짧은 계획으로 바꿉니다.

새 프로젝트일 때 자동

오류 질문

"안 돼요"라고만 해도 됩니다. 무엇을 했고 무엇이 보였는지 물은 뒤 정확히 고칩니다.

문제를 알릴 때 자동

개발일지

DEVLOG.md 파일에 결정, 꼭 기억할 것, 열린 문제를 적어 둡니다.

매 세션 자동으로 읽힘

보안 점검

흔한 실수 12가지를 찾아 쉬운 말로 보고합니다.

위험한 변경 뒤, 출시 전

디자인 도구

화면은 피그마, 로고와 이미지는 캔바. Claude가 골라서 씁니다.

첫 사용 때 로그인 필요

직접 부르고 싶을 때

평소처럼 말하면 됩니다. 예: "보안 점검해줘", "개발일지 정리해줘", "처음부터 다시 물어봐줘".

4. 문제가 생겼을 때

"안 돼요", "고쳐줘"라고만 말해도 됩니다. Claude가 추측으로 고치지 않고, 정확히 무엇이 문제인지부터 찾습니다.

Claude직접 확인바뀐 코드, 오류 기록, 실행
→
나질문에 답하기최대 4개, 고르는 형식
→
Claude재현같은 문제를 직접 일으킴
→
Claude수정원인 하나에 수정 하나
→
나확인알려준 방법대로 눌러 보기

예시 대화

아까는 됐는데 지금 안 돼. 고쳐줘
방금 바뀐 부분을 먼저 확인했어요. 정확히 고치려고 세 가지만 여쭤볼게요.
① 직전에 무엇을 누르셨나요?
② 무엇이 보였나요? 아무 반응 없음 / 오류 문구 / 틀린 결과 / 잘 모름
③ 매번 그런가요? 매번 / 가끔 / 한 번
저장 버튼 눌렀고, 아무 반응 없어. 매번 그래
같은 문제를 재현했어요. 제목이 비어 있을 때 저장이 멈춥니다. 고친 뒤 확인 방법을 알려드릴게요.

흐름을 보여주는 예시입니다. 실제 문구는 달라집니다.

Claude가 물을 수 있는 것

  • 직전에 무엇을 하고 있었나
  • 무엇이 보였나 (오류 문구는 화면 캡처가 가장 좋음)
  • 원래 어떻게 되길 기대했나
  • 매번 그런가, 가끔 그런가
  • 휴대폰인가 컴퓨터인가
  • 로그인 상태나 특정 내용에서만 그런가
  • 마지막으로 된 게 언제인가

이 중 필요한 것만 최대 4개를 묻습니다. Claude가 직접 확인할 수 있는 것은 묻지 않습니다. 두 번 고쳐도 안 되면 멈추고 선택지를 줍니다.

5. 안전 검사가 막는 것

AI의 판단이 아니라 고정된 규칙으로 작동합니다. 그래서 대화가 길어져도 항상 실행됩니다.

이런 일이 생기려 하면동작
비밀 파일(.env, 개인키)이나 비밀키가 git에 저장되려 함차단
공식 등록소에 존재하지 않는 패키지를 설치하려 함차단
GitHub 저장소를 공개로 만들거나 공개로 바꾸려 함확인 요구
되돌릴 수 없는 명령: 강제 덮어쓰기, 저장 안 한 변경 버리기, 프로젝트 밖 폴더 삭제, 실서비스 배포확인 요구

6. 누가 무엇을 정하나

Claude가 나에게 묻는 것은 돈, 되돌릴 수 없는 일, 개인정보, 제품의 방향입니다.

Claude가 알아서

  • 어떤 도구를 쓸지
  • 파일을 어떻게 나눌지
  • 단순한 오류 고치기

무료이고, 되돌릴 수 있고, 프로젝트 안의 일. 무엇을 골랐는지 한 줄로 알려줍니다.

먼저 나에게 묻기

  • 돈이 드는 일
  • 되돌릴 수 없는 일
  • 개인정보를 다루는 일
  • 외부 서비스 가입
  • 제품이 하는 일을 바꾸기

내가 직접

  • 비밀번호 입력
  • 결제 정보 입력
  • 약관 동의

Claude는 이 일을 대신하지 않습니다.

내 말에 무조건 동의하지 않습니다

내가 요청한 것보다 나은 방법이 보이면 Claude가 숫자나 확인 가능한 사실과 함께 제안합니다. 다만 제안만 하고 내 답을 기다립니다. 먼저 바꿔 놓고 나중에 알리지 않습니다.

7. 개발일지는 이렇게 생겼습니다

프로젝트 폴더의 DEVLOG.md 파일입니다. 다음에 다시 열어도 Claude가 이 파일부터 읽고 이어서 작업합니다.

## Now지금 어디까지 했고, 다음에 할 일
## Pinned절대 잊으면 안 되는 것: 결정한 것, 가입한 서비스, 드는 비용. Claude가 마음대로 줄이지 않습니다.
## Open issues열린 문제: 지금 고칠 것 / 나중에 / 무시해도 됨
## Log날짜별 작업 기록. 새 버전으로 넘어갈 때 이 부분만 요약됩니다.

8. 꼭 알아둘 한계

앱을 안전하게 만들어 주지는 않습니다

  • 흔한 실수를 잡아낼 뿐입니다. 결제, 건강 정보, 신분증 번호, 어린이 정보를 다룬다면 출시 전에 전문가 점검을 받으세요.
  • Claude가 실행하는 명령만 봅니다. 내가 터미널에 직접 입력한 명령은 검사하지 않습니다.
  • 비밀키는 흔한 형식만 알아봅니다. 패키지 확인은 npm, pnpm, yarn, bun만 됩니다.
  • 포토샵은 지원하지 않습니다.
  • 작업 규칙, 시작 질문, 오류 질문은 코드가 아니라 지침입니다. Claude가 대부분 따르지만 항상은 아닙니다. 안전 검사만 코드라서 항상 실행됩니다.
  • 실제 Claude Code 세션에서의 동작은 아직 확인하지 못했습니다. 자동 테스트 91건만 통과한 상태입니다.

9. 끄는 법

지금 방식에서는 --plugin-dir 없이 claude만 실행하면 꺼진 상태입니다. 설치해서 쓰는 경우에는 /plugin에서 nondev-kit를 끄거나 삭제합니다. DEVLOG.md 파일은 그대로 남습니다.
