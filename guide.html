vibe-starter 사용 안내

개발자가 아닌 사람이 AI로 웹사이트나 앱을 만들 때 쓰는 Claude Code 플러그인입니다. 무엇을 만들지는 내가 정하고, 어떻게 만들지는 Claude가 정합니다.

1. 시작하는 법

아직 GitHub에 올리지 않았기 때문에, 지금은 이 컴퓨터에 있는 폴더를 직접 불러와서 씁니다.

1

터미널에서 Claude Code에 로그인하기

터미널을 열고 claude를 실행한 뒤 /login을 입력합니다. 한 번만 하면 됩니다.

2

새 프로젝트용 빈 폴더 만들기

만들 앱이 들어갈 폴더입니다. 이름은 자유롭게 정하면 됩니다.

mkdir ~/Desktop/my-app
cd ~/Desktop/my-app
3

플러그인을 켠 채로 Claude Code 실행하기

claude --plugin-dir "/Users/kimtaemin/Desktop/private skills"

이 방식은 실행할 때마다 위 명령으로 시작해야 플러그인이 켜집니다.

4

만들고 싶은 것을 말하기

"앱 만들어줘"처럼 막연하게 말해도 됩니다. 그러면 Claude가 바로 만들지 않고 먼저 질문합니다.

GitHub에 올린 뒤에는 (아직 안 됨)

Claude Code 안에서 아래 두 줄을 한 번만 입력하면 그 뒤로는 자동으로 켜집니다. OWNER 자리에는 GitHub 계정 이름이 들어갑니다.

/plugin marketplace add OWNER/vibe-starter
/plugin install vibe-starter@vibe-starter

2. 쓰면 이렇게 흘러갑니다

파란 글씨는 내가 하는 일, 초록 글씨는 Claude가 하는 일입니다.

나말하기"앱 만들어줘"
→
Claude질문하기고르는 질문 몇 개
→
나계획 확인짧은 요약에 "좋아"
→
Claude만들기쉬운 말로 설명하며
→
Claude점검·기록보안 점검, 개발일지

예시 대화

가계부 앱 만들어줘
좋아요. 만들기 전에 몇 가지만 여쭤볼게요. 누가 쓰나요? ① 나 혼자 ② 가족이나 친구 몇 명 ③ 누구나
① 나 혼자
가장 중요한 기능 하나만 고른다면요? ① 지출 빠르게 적기 ② 월별 통계 보기 ③ 예산 넘으면 알림
①
정리하면 이렇습니다: 혼자 쓰는 웹 가계부, 핵심은 지출 빠르게 적기, 로그인 없음, 비용 0원. 이대로 시작할까요?

실제 질문 문구는 상황에 따라 달라집니다. 위는 흐름을 보여주는 예시입니다.

3. 들어 있는 것 6가지

대부분 자동으로 작동합니다. 따로 외울 명령은 없습니다.

작업 규칙

쉬운 말로 설명하기, Claude가 혼자 정해도 되는 범위, 기본 보안 습관.

매 세션 자동

안전 검사

위험한 명령 4종류를 실행 전에 막거나 확인을 요구합니다.

모든 명령 전 자동

시작 질문

막연한 요청을 고르는 질문 몇 개로 짧은 계획으로 바꿉니다.

새 프로젝트일 때 자동

개발일지

DEVLOG.md 파일에 결정, 꼭 기억할 것, 열린 문제를 적어 둡니다.

매 세션 자동으로 읽힘

보안 점검

흔한 실수 12가지를 찾아 쉬운 말로 보고합니다.

위험한 변경 뒤, 출시 전

디자인 도구

화면은 피그마, 로고와 이미지는 캔바. Claude가 골라서 씁니다.

첫 사용 때 로그인 필요

직접 부르고 싶을 때

평소처럼 말하면 됩니다. 예: "보안 점검해줘", "개발일지 정리해줘", "처음부터 다시 물어봐줘".

4. 안전 검사가 막는 것

AI의 판단이 아니라 고정된 규칙으로 작동합니다. 그래서 대화가 길어져도 항상 실행됩니다.

이런 일이 생기려 하면동작
비밀 파일(.env, 개인키)이나 비밀키가 git에 저장되려 함차단
공식 등록소에 존재하지 않는 패키지를 설치하려 함차단
GitHub 저장소를 공개로 만들거나 공개로 바꾸려 함확인 요구
되돌릴 수 없는 명령: 강제 덮어쓰기, 저장 안 한 변경 버리기, 프로젝트 밖 폴더 삭제, 실서비스 배포확인 요구

5. 누가 무엇을 정하나

Claude가 나에게 묻는 것은 돈, 되돌릴 수 없는 일, 개인정보, 제품의 방향입니다.

Claude가 알아서

  • 어떤 도구를 쓸지
  • 파일을 어떻게 나눌지
  • 단순한 오류 고치기

무료이고, 되돌릴 수 있고, 프로젝트 안의 일. 무엇을 골랐는지 한 줄로 알려줍니다.

먼저 나에게 묻기

  • 돈이 드는 일
  • 되돌릴 수 없는 일
  • 개인정보를 다루는 일
  • 외부 서비스 가입
  • 제품이 하는 일을 바꾸기

내가 직접

  • 비밀번호 입력
  • 결제 정보 입력
  • 약관 동의

Claude는 이 일을 대신하지 않습니다.

6. 개발일지는 이렇게 생겼습니다

프로젝트 폴더의 DEVLOG.md 파일입니다. 다음에 다시 열어도 Claude가 이 파일부터 읽고 이어서 작업합니다.

## Now지금 어디까지 했고, 다음에 할 일
## Pinned절대 잊으면 안 되는 것: 결정한 것, 가입한 서비스, 드는 비용. Claude가 마음대로 줄이지 않습니다.
## Open issues열린 문제: 지금 고칠 것 / 나중에 / 무시해도 됨
## Log날짜별 작업 기록. 새 버전으로 넘어갈 때 이 부분만 요약됩니다.

7. 꼭 알아둘 한계

앱을 안전하게 만들어 주지는 않습니다

  • 흔한 실수를 잡아낼 뿐입니다. 결제, 건강 정보, 신분증 번호, 어린이 정보를 다룬다면 출시 전에 전문가 점검을 받으세요.
  • Claude가 실행하는 명령만 봅니다. 내가 터미널에 직접 입력한 명령은 검사하지 않습니다.
  • 비밀키는 흔한 형식만 알아봅니다. 패키지 확인은 npm, pnpm, yarn, bun만 됩니다.
  • 포토샵은 지원하지 않습니다.
  • 실제 Claude Code 세션에서의 동작은 아직 확인하지 못했습니다. 자동 테스트 91건만 통과한 상태입니다.

8. 끄는 법

지금 방식에서는 --plugin-dir 없이 claude만 실행하면 꺼진 상태입니다. 설치해서 쓰는 경우에는 /plugin에서 vibe-starter를 끄거나 삭제합니다. DEVLOG.md 파일은 그대로 남습니다.
